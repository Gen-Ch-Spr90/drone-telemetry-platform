# Real Drone Data — Validation Path

## Current Testing Status

The platform has been developed and tested against **synthetic flight data**
generated by `tools/synthetic_flight_generator.py`. The generator models the
DJI Mavic 2 Pro flight envelope:

- 400 ft FAA ceiling
- ~12 m/s cruise speed
- ~30-minute max flight time
- Realistic battery drain curve
- GPS jitter and signal-loss patterns
- Takeoff / waypoint / hover / RTH / landing phases

The synthetic pipeline is verified by **4 Testcontainers integration tests**
that exercise the full stack: CSV → Spring Boot → PostGIS → event detection →
GeoJSON. Real drone flight logs have **not yet been ingested**.

This document describes how to validate the platform against real data.

## Why Synthetic First

Building the ingestion pipeline against synthetic data first is deliberate:

1. **Reproducibility** — a fixed-seed generator produces identical test inputs
   every run, enabling deterministic integration tests.
2. **Edge case coverage** — low battery, weak signal, and geofence-breach
   scenarios are generated on demand without waiting for real flights.
3. **Iteration speed** — a 4-minute real flight takes 4 minutes to record;
   a synthetic CSV generates in ~40 ms.
4. **Isolation** — pipeline bugs are separated from data-quality issues in
   real logs.

This mirrors standard practice in telemetry, IoT, and aerospace: model the
system, verify the pipeline, then validate against real hardware.

## How to Export Real DJI Logs

### Option A — DJI Fly App (easiest)

1. Open the **DJI Fly** app on your phone (paired with the Mavic 2 Pro)
2. Go to **Profile → Flight Records**
3. Pick any flight
4. Tap the **...** menu → **Export to CSV**
5. Email the CSV to yourself or AirDrop to your Mac

### Option B — DJI Assistant 2 (desktop)

1. Install **DJI Assistant 2** from dji.com
2. Connect the drone via USB
3. **Flight Logs → Export** — choose CSV format
4. Logs land in `~/Documents/DJI/` or a folder you select

### Option C — Airdata UAV (cloud, converts DAT → CSV)

1. Sign up at airdata.com (free tier is enough)
2. Upload your `.DAT` or `.txt` flight logs from the SD card
3. Export as CSV

## Expected CSV Columns

Our schema expects these columns (header row required):

| Column | Type | Notes |
|--------|------|-------|
| `flight_id` | UUID | Any consistent UUID for one flight |
| `recorded_at` | ISO 8601 timestamp | e.g. `2026-10-05T14:30:00Z` |
| `lat` | double | Decimal degrees |
| `lon` | double | Decimal degrees |
| `altitude_m` | double | Meters above takeoff |
| `speed_mps` | double | Meters per second |
| `heading_deg` | double | 0–360 |
| `battery_pct` | double | 0–100 |
| `satellites` | int | GPS satellite count |
| `signal_strength_dbm` | double | Negative dBm |
| `gimbal_pitch_deg` | double | Degrees |
| `gimbal_yaw_deg` | double | Degrees |

## Mapping DJI Columns to Our Schema

DJI's exported CSV uses different names. Typical mapping:

| DJI Column | Our Column | Transform |
|------------|-----------|-----------|
| `Time` | `recorded_at` | Parse to ISO 8601 |
| `GPS(0):Lat` or `Latitude` | `lat` | None |
| `GPS(0):Long` or `Longitude` | `lon` | None |
| `Height` or `Altitude` | `altitude_m` | Units check (m vs ft) |
| `Speed` or `Horizontal Speed` | `speed_mps` | Units check (m/s vs mph) |
| `Battery` | `battery_pct` | None |
| `Satellites` | `satellites` | None |
| `Signal` or `RC Signal` | `signal_strength_dbm` | Convert if in % |

**Action:** Export one real flight first. Compare its columns against this
table. Then either:

1. Write a small Python adapter (`tools/dji_to_csv.py`) that maps DJI columns
   to our schema and writes a normalized CSV, or
2. Manually reshape the CSV in a spreadsheet for the first validation flight.

Start with option 2 to validate the pipeline. Build the adapter (option 1)
once you know the exact DJI format.

## Validation Checklist

When you ingest your first real flight:

- [ ] CSV parses without errors (`flight_id` is consistent across rows)
- [ ] Flight row appears in `/api/flights`
- [ ] Point count in `/api/flights/{id}/points` matches CSV row count
- [ ] PostGIS `ST_X(position)` returns the expected longitude
- [ ] Events are detected as expected (battery, signal, geofence)
- [ ] Map renders the path on satellite imagery
- [ ] Grafana panels show the flight
- [ ] Compare statistics: max altitude, total distance, battery drain rate
      against the DJI Fly app's summary for the same flight

## If Real Data Doesn't Match

Common causes and fixes:

| Symptom | Likely Cause | Fix |
|---------|--------------|-----|
| Altitude off by ~3.28× | DJI exported feet, not meters | Divide by 3.28 in the adapter |
| Speed off by ~2.24× | MPH vs m/s | Divide by 2.24 |
| Timestamps drift by hours | Timezone not UTC | Force UTC at parse |
| Path zigzags | Rows not sorted by time | Sort on ingest |
| All points clustered | Wrong lat/lon column | Check DJI column order |
| No events detected | Thresholds too strict | Adjust LOW_BATTERY_PCT / WEAK_SIGNAL_DBM |
